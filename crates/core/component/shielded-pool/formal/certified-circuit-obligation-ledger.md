# Certified circuit obligation ledger

This reviewed protocol-side checklist covers the two fixed-padded NoteReshape
families, Transfer 2x2, and shielded ICS-20 Withdrawal 2x1. Generated row facts
are evidence for these obligations; they never define the obligations.

## Shared certification boundary

| ID | Obligation | Circuit fact | External fact |
|---|---|---|---|
| `CERT-EXACT-RELATION` | The theorem ranges over every row of the source-compiled SR1CS selected by the deployed PK/VK. | Authenticated row IR, exact template witnesses, exhaustive capstone, and typed bindings. | Source/SR1CS/key metadata and deployed prove/verify receipt byte-match. |
| `CERT-FIXED-FAMILY` | The decoded action has the certified fixed arity and the verifier uses that family's deployed key. | The statement hash and every fixed slot are constrained. | Domain validation rejects other shapes; verification selects the matching fixed key. |
| `CERT-PROOF-CANONICAL-ENCODING` | Serialized proof bytes identify one canonical Groth16 proof before pairing verification. | None; proof encoding is not an R1CS relation. | The shared strict decoder enforces exact length, complete consumption, canonical reserialization, and rejection of arkworks infinity aliases for all four families. |
| `CERT-PROOF-VERIFICATION` | The action is accepted only if Groth16 verification succeeds for its proof and native-projected public input. This is independent of selecting the correct family key. | The exact source-compiled relation constrains the projected public input. | The runtime verifier returns success under the already-selected deployed verification key; malformed or relation-invalid proofs are rejected. |
| `CERT-PUBLIC-PROJECTION` | The verifier's sole public input is the native domain-separated projection of the decoded action body. | Exact statement-hash rows bind every listed field in order. | Rust and Go reconstruct the same canonical field vector and hash. |
| `CERT-SPEND-AUTH` | Every fixed public randomized key, including a dummy slot, is nonidentity and has a spend-authorization signature over the enclosing transaction effect hash. Transfer's effect hash commits the exact proof-bound compliance ciphertext and metadata, preventing a delegated builder from replacing encryption randomness or payload bytes after authorization. | Real branches bind RKs to the shared authorization key; dummy RKs remain statement-bound. | Consensus rejects identity RK before exact signature verification for every slot; only the separately checked witness anchor is normalized out of the action effect hash. |
| `CERT-TX-BINDING` | Every transaction containing any of the four certified proofs or a fee-funding proof has a nonidentity aggregate action/fee balance key and a binding signature over the final authorization hash. The identity-key all-zero sentinel is outside these target accepted languages and is reserved for transactions with no shielded proofs. | Each action balance commitment is statement-bound. | Consensus checks `num_proofs() > 0` before requiring nonidentity aggregate BvK and ordinary authorization-hash verification; construction rejects zero aggregate blinding for proof-bearing plans. The authorization hash binds the ordered spend-authorization bytes, preventing same-key signature permutation malleability without an RK-uniqueness rule. |
| `CERT-SCT-STATE` | Every real spend uses the enclosing transaction anchor and every proof-bound nullifier is consumed exactly once. | Membership, nullifier, selector, and statement relations bind each fixed slot. | The anchor is live; nullifiers are fresh and transaction-wide unique; insertion is atomic. |
| `CERT-OUTPUT-STATE` | Every proof-bound output commitment is persisted only if the whole transaction is accepted. | Output commitments are statement-bound. | Output insertion and all other action effects commit atomically. |
| `CERT-BODY-PROJECTION` | Consensus decoding admits one authoritative canonical fixed-shape action-body projection. | The circuit binds that decoded action projection to one statement. | Canonical body decoders reject wrong arity, unknown families, malformed encodings, and stale cached body projections. |

## Honest construction boundary

These obligations describe wallet construction. They are deliberately absent
from the consensus-accepted relation and cannot be used to justify acceptance
of an adversarially constructed action.

| ID | Construction obligation | Consensus acceptance | Construction evidence |
|---|---|---|---|
| `CONSTRUCTION-OUTGOING-VIEW` | Every real and synthetic output key is wrapped under the exact aggregate balance commitment serialized in the action body. | None; malformed outgoing-view wrapping does not invalidate an otherwise valid action. | Family construction and recovery regressions unwrap every output only under the serialized commitment. |
| `CONSTRUCTION-PLAN-PROJECTION` | Honest plan construction and checked plan decoding admit one authoritative canonical set of fixed-shape private and public action facts. | Only the derived body is consensus decoded; the private plan is never a consensus input. | Canonical plan decoders reject malformed scalars, missing membership facts, wrong arity, mixed senders, and stale cached projections. |
| `CONSTRUCTION-TRANSFER-NONCE` | Honest Transfer construction samples one unpredictable compliance nonce root per action, distinct from sibling and fee-funding Transfer actions, and rejection-samples nonzero tier scalars. | None; nonce freshness and uniqueness are privacy premises, not accepted-language constraints. | Wallet construction and nonce-domain regressions exercise fresh roots, transaction-wide separation, and nonzero scalar sampling. |

## NoteReshape families

| ID | Obligation | Circuit fact | External fact |
|---|---|---|---|
| `NR-SHAPE` | The selected family has its exact input/output arity, minimum real-input count, and an `is_dummy = 0` real prefix followed by an `is_dummy = 1` dummy suffix. | Boolean `is_dummy` selectors, suffix ordering, count range, and fixed family arity. | The planner and decoder select the matching family. |
| `NR-SHARED-ADDRESS` | Every committed input and output uses one asset ID, diversified generator, and canonical derived transmission encoding. The authorization key, shared diversified generator, and derived transmission point are non-identity, and the reduced IVK is nonzero. | One shared context; one DTK derivation and compression fan out to every note commitment. Separate exact inverse rows guard `auth.ak.x`, `shared.div_gen.x`, `auth.ivk_reduced`, and the computed shared transmission `x` in every fixed family. | Owner uniqueness for distinct `(nk, ak_s)` pairs is conditional on `ZK-ASSUME-IVK-HASH-TO-SCALAR-BINDING`, the collision resistance of the exact Poseidon-to-scalar map after reduction modulo `r`. |
| `NR-INPUT-COMMITMENT` | Every real input commitment opens to its amount/blinding and the canonical shared context. Dummy slots have no commitment obligation. | Conditional real note-commitment relation. | None. |
| `NR-MEMBERSHIP` | Every real input is a member under the public anchor; dummy membership cannot substitute for a real input. | Conditional real path equality and branch constraints. | `CERT-SCT-STATE`. |
| `NR-NULLIFIER` | Real (`is_dummy = 0`) nullifiers derive from the real note; dummy (`is_dummy = 1`) nullifiers derive from the slot seed and cannot create value. | The `is_dummy = 1` branch selects the synthetic nullifier and forces the note amount to zero; the `is_dummy = 0` branch selects the note-derived nullifier. | `CERT-SCT-STATE`. |
| `NR-AUTHORIZATION` | Each real RK is the shared AK randomized by that slot's randomizer. | Real-branch RVK equivalence and RK transcript binding. | `CERT-SPEND-AUTH`. |
| `NR-OUTPUT-COMMITMENT` | Every output is an ordinary note commitment in the canonical shared context. | Note-commitment relation for every output. | Output padding to zero-value notes is planner policy only. |
| `NR-CONSERVATION` | Input and output amounts conserve the one shared asset and the balance commitment uses the action blinding. | Exact amount equality and balance-blinding commitment/equivalence. | None. |
| `NR-STATEMENT` | The public hash binds the anchor, outputs, balance commitment, nullifiers, and RKs for the exact family. | Exact family statement transcript. | `CERT-PUBLIC-PROJECTION`. |
| `NR-ROUTING` | The owner routing tag uses the protocol-selected precision and the stable word derived from the shared transmission key. | Exact parameter hash, precision ordering, route-word hash, nonce-derived suffix, 32-bit range, and public-tag equality. | None. |

## Transfer 2x2

| ID | Obligation | Circuit fact | External fact |
|---|---|---|---|
| `T-SHAPE` | Transfer has one required spend, one real-or-dummy optional spend, one receiver output, and one change output. | The optional `is_dummy` selector is Boolean: zero selects the complete real relation and one selects the synthetic dummy relation. | Body, signatures, output compliance encoding, and proof key have fixed 2x2 shape. |
| `T-SENDER` | Both spends and change use one canonically derived sender address and asset; the receiver has its independently constrained address. The authorization key, sender diversified generator, and sender transmission point are non-identity, and the reduced IVK is nonzero. | Shared DTK/canonical encodings fan out directly to both spend commitments and change. Exact inverse rows bind the authorization, generator, IVK, and claimed sender transmission roles. | Distinct owner material remains computationally bound by `ZK-ASSUME-IVK-HASH-TO-SCALAR-BINDING`. |
| `T-SPENDS` | The required spend is real; the optional spend is complete and real when `is_dummy = 0`, or a zero-value synthetic dummy when `is_dummy = 1`. | Commitment, membership, nullifier, RK, amount, and selector relations use that exact polarity. | `CERT-SPEND-AUTH` and `CERT-SCT-STATE`. |
| `T-OUTPUTS` | Receiver and change commitments open to the constrained values and addresses. Every output owner uses non-identity diversified-generator and transmission points, so Transfer cannot create an identity-address note. | Both note commitments and their shared asset are constrained. The receiver has exact Decaf `x != 0` rows for its generator and transmission key; change inherits both guarded sender points. | The proof-bound payloads are persisted; ciphertext correctness beyond circuit-bound fields is not inferred. |
| `T-ASSET-REGISTRY` | The nonzero asset leaf/path proves regulated membership or ordered-gap non-membership under the claimed asset root; the zero-valued structural sentinel is never an asset policy. | Exact parameter/ring sub-hashes, compact leaf hash, path, Boolean classification, nonzero asset assertion, and ordered-gap relation. | The root is current, structurally well formed, and reachable only through authorized policy admissions that reject identity detection/ring keys before state mutation. |
| `T-USER-REGISTRY` | Regulated sender and receiver v3 leaves match the complete constrained address, asset, policy slot, and compliance root. | Six-field leaf derivations include diversified-generator and transmission-key encodings plus asset, slot, derivation, and 251-bit-canonical `d`; paths, threshold/slot selection, and regulated gates are exact. The circuit does not assert `d ≠ 0`. | The recent append-only user root contains only authorized admissions with nonzero leaf derivations valid at admission time. |
| `T-COMPLIANCE-TRANSCRIPT` | Detection, sender, and output ciphertexts, salts, ACK/shared-secret derivation, the regulation-gated threshold comparison, routing-role permutation, and factored metadata are mutually consistent. Unregulated transfers always produce `isFlagged = 0`; regulated transfers flag exactly when the receiver amount reaches the authenticated registered threshold. | Exact Poseidon, Decaf, threshold-gate, unconditional encryption, and metadata-binding row relations. Each address disclosure plaintext canonically packs the diversified-generator and transmission-key encodings in that order. Detection binds the exact asset and salt, a 32-bit sender slot plus flag and routing-swap bits, and a 32-bit receiver slot. | Fixed ciphertext and metadata records decode canonically; retired PRE/upload material is rejected; input compliance ciphertexts are empty. Nonce freshness, nonce uniqueness, and nonzero scalar sampling are separately tracked by `CONSTRUCTION-TRANSFER-NONCE` and are not consensus-acceptance facts. |
| `T-CONSERVATION` | The circuit-computed action balance commitment binds `required + optional - receiver - change` and its blinding, then the transaction binding signature enforces conservation across every action and the fee. The computed point is canonically compressed into the statement without a second prover-chosen affine representation. | Four amount bounds, the exact signed net-balance ladder, deterministic value/blinding generators, and compression of the computed point. | `CERT-TX-BINDING`. |
| `T-TIMESTAMP` | The compliance transcript binds the action target timestamp. | Target timestamp participates in the proof statement and compliance proofs. | Consensus rejects zero independently of block time, rejects negative signed consensus time before conversion, and enforces the inclusive fixed ±3600-second drift window around current consensus time. |
| `T-STATEMENT` | The v4 public hash binds all 41 native Transfer fields in their exact order. | Exact multi-block statement transcript and exact source-level field-index seam regression. | `CERT-PUBLIC-PROJECTION`; interpreting one Poseidon output as an injective body binding additionally assumes `ZK-ASSUME-PUBLIC-INPUT-HASH-CR`. |
| `T-ROUTING` | The fixed two-slot bundle privately selects class precision, derives sender and receiver words, permutes their roles, and substitutes a nonce-derived filler only for unregulated no-change. | Exact parameter hash/order, both route-word hashes, permutation hash, meaningful/filler selectors, suffix hashes, 32-bit ranges, public-tag equalities, and reuse of the permutation bit in detection encryption. | None. |

## Shielded ICS-20 Withdrawal 2x1

| ID | Obligation | Circuit fact | External fact |
|---|---|---|---|
| `W-SHAPE` | Withdrawal has one required spend, one real-or-dummy optional spend, and one sender-owned change output. | The optional `is_dummy` selector is Boolean: zero selects the complete real relation and one selects the synthetic dummy relation. | Body, signatures, family ID, and proof key have fixed 2x1 shape. |
| `W-SENDER` | Both spends and change use one canonically derived sender address and asset. The authorization key, sender diversified generator, and computed sender transmission point are non-identity, and the reduced IVK is nonzero. The regulated-user v3 leaf binds the complete address. | Shared DTK, canonical encodings, six-field compliance leaf, and note-commitment inputs are joined exactly. Separate exact inverse rows guard the authorization key, sender generator, reduced IVK, and computed sender transmission. | User admission accepts only canonical address encodings. Distinct owner material remains computationally bound by `ZK-ASSUME-IVK-HASH-TO-SCALAR-BINDING`. |
| `W-SPENDS` | The required spend is real; the optional spend is complete and real when `is_dummy = 0`, or a zero-value synthetic dummy when `is_dummy = 1`. | Commitment, membership, nullifier, RK, amount, and selector relations use that exact polarity. | `CERT-SPEND-AUTH` and `CERT-SCT-STATE`. |
| `W-CHANGE` | The one change commitment opens to the constrained sender-owned note, including the padded zero-value case. | Exact note-commitment relation. | The proof-bound payload is persisted; ciphertext correctness beyond circuit-bound fields is not inferred. |
| `W-ASSET-REGISTRY` | The nonzero withdrawn asset proves regulated membership or ordered-gap non-membership under the claimed asset root; the zero-valued structural sentinel is never an asset policy. | The compact leaf directly binds value, next index/value, and committed parameter/ring hashes; its path, Boolean classification, nonzero asset assertion, and ordered-gap relation are exact. | The root is current, structurally well formed, and reachable only through authorized native policy registration/update transitions whose canonical sub-hashes cross-index the committed leaf. |
| `W-USER-REGISTRY` | A regulated sender v3 leaf matches the complete constrained sender address, asset, policy slot, and compliance root. Withdrawal hashes `d` into that leaf but never interprets it as a scalar, so it deliberately makes no 251-bit circuit-range claim for `d`. | Six-field leaf derivation includes diversified-generator encoding, transmission encoding, asset, slot, derivation, and `d`; path and regulated gate are exact. | The recent append-only user root contains only authorized admissions with native `d` encodings valid at admission time. |
| `W-CONSERVATION` | Spend value equals the outbound value plus change, and the balance commitment contains only the action blinding. | Amount bounds, outbound asset/amount binding, conservation, the computed balance ladder, and the canonical Decaf compression/body-encoding join. | `CERT-TX-BINDING`. |
| `W-PAYLOAD` | The four public limbs are the consecutive 128-bit little-endian chunks of the embedded withdrawal effect hash. | All limbs, outbound asset, and outbound amount are statement-bound. | One canonical payload encoding with deprecated compatibility and other noncanonical encodings rejected rather than normalized, BLAKE2b-512 collision resistance, nonzero amount, nonzero exactly minute-rounded timeout, canonically encodable transparent-address mode, exact body projection, and—when a current native policy exists—authorization of the effect-hashed route by that policy cross-indexed to the committed parameter/ring hashes. |
| `W-STATE` | The enabled ICS-20 state machine accepts and executes the exact proof-bound payload together with nullifier/output effects. | Circuit-bound withdrawal intent cannot change independently. | IBC withdrawal enablement, cached state checks, packet execution, and the entire action transition are atomic. |
| `W-TIMESTAMP` | The proof statement binds the action target timestamp. | Target timestamp participates in the public statement; it is not an input to the sender compliance leaf or path. | Consensus rejects zero independently of block time, rejects negative signed consensus time before conversion, and enforces the inclusive fixed ±3600-second drift window around current consensus time. |
| `W-STATEMENT` | The public hash binds all 16 native Withdrawal fields in their exact order. | Exact three-block statement transcript. | `CERT-PUBLIC-PROJECTION`. |
| `W-ROUTING` | The sender routing tag remains meaningful even when change is dummy and uses the privately selected class precision. | Exact parameter hash/order, sender route-word hash, nonce-derived suffix, 32-bit range, and public-tag equality. | None. |

The family adapters consume every typed circuit fact. The independence gate
hashes this ledger with the handwritten protocol models and forbids generated
imports. Witness-role checks require every compiled field to have a reviewed
obligation and actual polynomial influence in at least one deployed row.
