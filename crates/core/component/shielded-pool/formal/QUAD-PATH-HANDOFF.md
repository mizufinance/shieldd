# Quad Merkle Path Soundness — Handoff

Status of the `VerifyQuadPath` (compliance quad Merkle tree) soundness effort.
Stage numbering follows the spike plan: Stage 2 = per-layer Hash4 gadget,
Stage 3 = 16-layer path composition, Stage 4 = whole-circuit export + stamp.

## Stage 2 — Poseidon377 Hash4 gadget — DONE (certified)

The per-layer hash of `VerifyQuadPath` is `Poseidon377Hash4` (rate-4, t=5). It is
now proved by `verify-r1cs`, the same trust basis as `gadget-poseidon2` /
`gadget-nullifier`:

- Gadget: `PoseidonHash4Gadget` ([gadgets_constraint.go](../../../../tools/gnark/internal/circuits/gadgets_constraint.go)),
  label `gadget-poseidon-hash4` in gnarkctl.
- R1CS export: `acl2/generated/gadget-poseidon-hash4-r1cs.lisp` (356 constraints,
  71 S-boxes = 40 full + 31 partial rounds). Reproducible; gate stale-checks it.
- Proof: `acl2/hash4-proof.lisp` — `verify-r1cs` of
  `OUT = poseidon377-hash4-r1cs-axe(DOMAIN,IN0..IN3)`. **Certified, "Proved
  MAIN_CASE", 2.3s under acl2p.** Generated by `acl2/gen-hash4-proof.py` (parses
  the export, emits 71 pow17-chain rewrite rules + the verify-r1cs form).
- Fidelity: `TestAxeExportFidelityPoseidonHash4` — axe export == gnark's solved
  witness. Green.
- Gate: export stale-check + `certify_with_cert_pl generated/gadget-poseidon-hash4-r1cs`
  + `certify_with_cert_pl hash4-proof` + `check_artifact_stamp hash4-proof`.
- Ledger: `gadget-poseidon-hash4` row = `proved`; artifact
  `acl2/hash4-proof-artifact.txt` (+ `.sha256`).

The `gen-hash4-proof.py` convention (reverse-engineered from poseidon2-proof):
multiplicative coeffs signed-normalized (k-p when k>p/2, bridged by the
coeff-normalization rule); **additive round constants kept raw/positive** (no
rule bridges a sign-flipped additive constant — this was the one bug, fixed);
lincomb assembled constant-first then wire-terms in reverse export order,
right-folded with `add`.

## Stage 3 — 16-layer composition — OPEN (large; cheap route measured dead)

`VerifyQuadPath` = 16 layers; each: 2 position bits → 4 index indicators
(Mul/Sub, the proved bool-select/iszero family) → 4 Selects placing `current`
among 3 siblings → one Hash4 → next `current`. `ComplianceQuadTreeDepth = 16`.
Tree collision-resistance (binding) is an **assumption-ledger entry**, not a
proof obligation.

### Decisive measurement (do not re-run): the cheap citability route is dead.
To compose layers you need each layer's hash as a **citable** `holdp ⇒ spec`
lemma (valuation form), so `r1cs-constraints-holdp-of-rename-cons` can transport
it ×16. The cheap way to mint citability is `defthm-axe-r1cs` (b1-foundation) —
but it embeds `(dag2term <lifted>)` in the theorem statement. Probe result on the
hash4 lifted DAG: **3341 DAG nodes, but dag2term acl2-count = 5.8×10⁷⁹.** Same
term/shared-DAG wall as the 2022-constraint lex ladder. `defthm-axe-r1cs` cannot
state the hash4 layer. Confirmed, dead at this scale.

### Why citability is genuinely hard here.
`verify-r1cs` closes only because its clause processor runs a `:subst` phase
(Gaussian-style elimination of the 355 internal wires). Ordinary `defthm`
rewriting cannot reproduce that substitution. The b1.9a IsZero-block citable
lemma did the substitution by hand because it was 2 constraints / 1 wire; the
hash4 layer is 356 constraints / 355 wires — the explicitly-deferred b1.9b-class
telescoping effort.

### Two credible routes (both large — pick before investing):

1. **Composition (what the spike plan assumed).** Make one hash4 layer citable
   via hand-substitution direct-unfold (b1.9b-class), then transport ×16 with
   rename-cons, glue the select-block (small, b1.9a-style direct-unfold per
   layer), compose into a `root = iterated-hash4(...)` theorem. Modular; reuses
   the single hash4 proof. Cost: the hand-substitution of 355 wires is the hard,
   slow part.

2. **Whole-path `verify-r1cs` (no composition, no citability wall).** Export a
   `QuadPathGadget` wrapping all 16 layers (≈6000 constraints), write a
   `quad-path-r1cs-axe` spec (position decode + selects + 16× hash4 rounds),
   generate ~1136 pow17 chains (16×71, `gen-hash4-proof.py` already does the
   per-S-box emission), and run one `verify-r1cs`. Anonymous — same status class
   as poseidon2/nullifier/hash4, fine for a `proved` gate row. `verify-r1cs`
   scales here (it proved 5568-constraint AssetRegistryGap operand canonicity via
   shared DAG, no dag2term). Cost: authoring the quad-path spec with the select
   logic, and getting the Select constraints to discharge under the prover.

Recommendation: **route 2** (whole-path verify-r1cs) is the lower-risk path to a
`proved` quad-path row — it sidesteps the measured dag2term wall and the
355-wire hand-substitution entirely, and the chain emission is already
automated. Route 1 only wins if a citable, reusable layer lemma is independently
wanted.

### Scale probe results (depth-parametric `QuadPathNGadget`, exported & measured)

Exported `gadget-quad-path-{1,2,4,16}` (depth-parametric `verifyQuadPathN`).
Constraint counts: **depth-1 = 368, depth-2 = 734, depth-4 = 1466, depth-16 =
5858** (≈366/layer = 356 hash + ~10 select/decode). The full path (5858) is
comparable to the already-proved 5568-constraint AssetRegistryGap operand
canonicity — so `verify-r1cs` lift+subst capacity is **not** the limiting factor.

Decisive structural finding from the depth-1 export (`/tmp/quad-path-1.lisp`,
368 constraints, wires LEAFHASH/POSITION/PATH-0-{0,1,2}/ROOT + INTERNAL-7..368):

1. **The hash sub-block reuses `poseidon377-hash4-r1cs-axe` verbatim.** The
   per-layer hash is `Poseidon377Hash4(api, 0, children)`. Its first-round S-box
   inputs are `RC_inK + childK` with the *same* round constants as the proved
   hash4 spec (e.g. in0 RC `5974593340237813855065980531800418392229182384079544474645411722799919145826`).
   So the whole-path spec is `(equal ROOT (poseidon377-hash4-r1cs-axe 0 child0
   child1 child2 child3))` per layer — **no new hash math, no new chains beyond
   re-pointing `gen-hash4-proof.py` at each layer's S-box slice.**

2. **The one new obstruction is the select block** (the route-2 cost the handoff
   flagged as "getting the Select constraints to discharge"). Per layer:
   `bit0,bit1 = INTERNAL-7,8` (boolean); decode `bit0 + 2·bit1 = POSITION`;
   index indicators `isIndex0=(1-b0)(1-b1)`, `isIndex1=b0(1-b1)`,
   `isIndex2=b1(1-b0)`, `isIndex3=b0·b1`; and the children are linear combos of
   sibling + select-product wires (`child0 = PATH-0-0 + INTERNAL-13`,
   `INTERNAL-13 = isIndex0·(LEAFHASH-PATH-0-0)`, etc.). Under `:subst` the decode
   constraint eliminates `bit0 = POSITION-2·bit1`, leaving children as
   bilinear normal forms in `POSITION`, the surviving bit, and the input
   differences. The spec's `childK` arguments must be authored to **match that
   subst normal form** — this is the real (tractable, but not yet exercised)
   authoring cost. It is the same select+output-glue class as AssetRegistryGap's
   still-open tail (plan Step 2), and reuses the proved `gadget-bool-select` /
   `gadget-iszero` reasoning.

### Depth-1 whole-path verify-r1cs — PROVED (certified)

`quad-path-1-proof.lisp` certifies: `verify-r1cs` of
`ROOT = poseidon377-hash4-r1cs-axe(DOMAIN, child0..child3)` over the 373-constraint
depth-1 export ("Proved MAIN_CASE", ~5s, 182155 steps). Route-2 is viable
end-to-end for a full layer (position decode + 4 Selects + Hash4). Key facts:

- **Domain threaded as a wire** (not the shipped literal 0): the quad-path gadgets
  now expose `Domain` so gnark does not constant-fold the lane-0 S-box, keeping the
  hash sub-block structurally identical to the proved standalone hash4 (71 S-boxes).
  `verifyQuadPathN(api, domain, leafHash, path, position)`.
- **Spec reuses `poseidon377-hash4-r1cs-axe` verbatim**; the 4 children are the
  arithmetic Selects, `child_k = build_lincomb(wire-part of round-0 input-lane k
  S-box :a)`. They MUST match the chain `E` nesting exactly — the Axe rule-list
  carries NO `pfield::add` reassociation, so a hand-written child in the wrong add
  order makes the lane chain miss, the 71-round hash expands, and the DAG blows the
  control stack. Deriving children from the export guarantees the match.
- **No select-block rewrite rules needed.** `:subst` discharges the bit-decode /
  index-indicator / select-product glue; only the 71 pow17 chains + the
  final-output helper are emitted (generator `gen-quad-path-1-proof.py`).
- **Control stack:** needs `SBCL_USER_ARGS="--control-stack-size 400"` (the default
  64 MB in `saved_acl2p` overflows; the select wires add DAG depth). The gate must
  export this for the quad-path cert.
- Exit code 43 from ACL2 is normal here (standalone hash4 exits 43 too); success
  signal is `.cert` existence, as `certify_with_cert_pl` already checks.

### Depth-N generalization (in progress) — multi-layer nesting

Depth-2 export (744 constraints) layout: `ToBinary(position, 2·depth)` front-loads
all bit booleans + one decode; then per layer: 4 index-indicator muls + select
products + a 71-S-box hash whose output constraint binds that layer's parent wire
(`PARENT_L`; top layer's = ROOT). Layer L>0's input-lane `current` references
`PARENT_{L-1}`. Plan for the general generator: detect S-box runs structurally,
group into layers of 71, build a **nested** spec
`ROOT = hash4(DOMAIN, sel_L(hash4(DOMAIN, sel_{L-1}(... LEAFHASH ...))))` by
substituting each layer's parent-wire token with the previous layer's nested hash
expression; emit 71 chains/layer + one final-output helper/layer. Validate on
depth-2 (riskiest: nesting collapse), then depth-16 is mechanical (×16 chains,
≈5858 constraints). Control stack will need raising further for depth-16.

### Depth-2 whole-path verify-r1cs — BLOCKED (honest checkpoint; row NOT promoted)

The depth-N generator (`acl2/gen-quad-path-n-proof.py`) is written and correct:
it detects S-box runs structurally (4 squarings + 1 mul), chunks into 71-S-box
layers, emits 71 pow17 chains/layer, and locates each layer's parent extraction
(`Sum coeff_i*lane_i`, coeffs = the t=5 MDS output row) in the inter-layer gap
where gnark inlines it into the next layer's select `:b`. Two spec modes:
`nested` (per-layer `parent_L = hash4(DOMAIN, children_L)` conjuncts, intermediate
final-lanes kept as bridge vars) and `top` (top conjunct only, eliminate
everything — the literal depth-1 recipe). Depth-2 export certified
(`generated/gadget-quad-path-2-r1cs`, 744 constraints, 142 S-boxes).

**Both modes hit the same wall and DO NOT certify.** The proof *mechanism* is
identical to the certified depth-1 (confirmed from the logs: rewrite set 1 grows
the DAG via hash expansion, `:subst` applies 1 candidate then "no suitable"
— exactly as depth-1 — and rule set 2 = the chains is where the proof closes).
The difference is pure DAG size and recursion depth:

| | post-rewrite DAG | rule-set-2 outcome | stack |
|--|--|--|--|
| depth-1 (PROVED) | 6162 nodes | "Rewriting proved case", instant | 200 MB ok |
| depth-2 | 12324 nodes | `CONTROL-STACK-EXHAUSTED` in `SIMPLIFY-TREE-AND-ADD-TO-DAG-FOR-R1CS-PROVER` | **8000 MB still fails** |

`SBCL_USER_ARGS="--control-stack-size N"` is honored (measured actual ≈ N/2 MB;
default 32 MB). Pushed actual stack 200 MB → 8000 MB (40×) for a 2× node count —
still exhausts at the identical frame. So the rule-set-2 rewrite recursion is
**super-linear per added layer**, not a tunable limit. Root cause: gnark
materializes **no parent wire** between layers (each layer's hash output is the
inlined `Sum coeff*lane` extraction), so the layer-0 and layer-1 hashes fuse into
one deeply-nested term; `SIMPLIFY-TREE-…` re-expands the shared nested subterms
as a tree (same shared-term blowup family as the measured dag2term = 5.8e79
citability wall). depth-16 is unreachable this way.

**Candidate fix (next, requires a gadget design change — get user buy-in):**
force gnark to **materialize each layer's parent as a single wire** (e.g. an
identity `NewHint` output `AssertIsEqual`d to the hash result, threaded as the
next layer's `current`). That replaces the inlined `Sum coeff*lane` extraction
with one linear constraint `PARENT_L = extraction` and a *single* wire the next
layer's selects reference — breaking the term nesting so each layer's hash stays
depth-bounded (depth-1-like) and `:subst` can eliminate `PARENT_L` cleanly as a
bridge. The proof gadget is scope-only (no fixtures, proves nothing on its own),
so the extra wire is acceptable provided a note records that the shipped inlined
`VerifyQuadPath` is equisatisfiable (the parent wire is determined). Then the
generator's bridge-lane logic collapses to single PARENT wires and depth-2 should
close per-layer-bounded; re-assess depth-16 stack after depth-2 is green.

Honest-residual status: depth-1 remains the only certified whole-path result; no
`gadget-quad-path` ledger row promoted. Artifacts on disk: `gen-quad-path-n-proof.py`,
`generated/gadget-quad-path-2-r1cs.{lisp,cert}`, the failed
`quad-path-2-proof.lisp` / `quad-path-2-top-proof.lisp` + their `.cert.out`
(control-stack backtraces) kept as the checkpoint evidence.
