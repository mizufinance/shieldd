# Quad Merkle Path Soundness — Handoff

Status of the `VerifyQuadPath` (compliance quad Merkle tree) soundness effort.
Stage numbering follows the spike plan: Stage 2 = per-layer Hash4 gadget,
Stage 3 = 16-layer path composition, Stage 4 = whole-circuit export + stamp.

## Stage 2 — Poseidon377 Hash4 gadget — DONE (certified)

The per-layer hash of `VerifyQuadPath` is `Poseidon377Hash4` (rate-4, t=5). It is
now proved by `verify-r1cs`, the same trust basis as `gadget-poseidon2` /
`gadget-nullifier`:

- Gadget: `PoseidonHash4Gadget` ([gadgets_constraint.go](../../../../tools/gnark/internal/circuits/gadgets_constraint.go)),
  label `gadget-poseidon-hash4` in gnarkctl.
- R1CS export: `acl2/generated/gadget-poseidon-hash4-r1cs.lisp` (356 constraints,
  71 S-boxes = 40 full + 31 partial rounds). Reproducible; gate stale-checks it.
- Proof: `acl2/hash4-proof.lisp` — `verify-r1cs` of
  `OUT = poseidon377-hash4-r1cs-axe(DOMAIN,IN0..IN3)`. **Certified, "Proved
  MAIN_CASE", 2.3s under acl2p.** Generated by `acl2/gen-hash4-proof.py` (parses
  the export, emits 71 pow17-chain rewrite rules + the verify-r1cs form).
- Fidelity: `TestAxeExportFidelityPoseidonHash4` — axe export == gnark's solved
  witness. Green.
- Gate: export stale-check + `certify_with_cert_pl generated/gadget-poseidon-hash4-r1cs`
  + `certify_with_cert_pl hash4-proof` + `check_artifact_stamp hash4-proof`.
- Ledger: `gadget-poseidon-hash4` row = `proved`; artifact
  `acl2/hash4-proof-artifact.txt` (+ `.sha256`).

The `gen-hash4-proof.py` convention (reverse-engineered from poseidon2-proof):
multiplicative coeffs signed-normalized (k-p when k>p/2, bridged by the
coeff-normalization rule); **additive round constants kept raw/positive** (no
rule bridges a sign-flipped additive constant — this was the one bug, fixed);
lincomb assembled constant-first then wire-terms in reverse export order,
right-folded with `add`.

## Stage 3 — 16-layer composition — OPEN (large; cheap route measured dead)

`VerifyQuadPath` = 16 layers; each: 2 position bits → 4 index indicators
(Mul/Sub, the proved bool-select/iszero family) → 4 Selects placing `current`
among 3 siblings → one Hash4 → next `current`. `ComplianceQuadTreeDepth = 16`.
Tree collision-resistance (binding) is an **assumption-ledger entry**, not a
proof obligation.

### Decisive measurement (do not re-run): the cheap citability route is dead.
To compose layers you need each layer's hash as a **citable** `holdp ⇒ spec`
lemma (valuation form), so `r1cs-constraints-holdp-of-rename-cons` can transport
it ×16. The cheap way to mint citability is `defthm-axe-r1cs` (b1-foundation) —
but it embeds `(dag2term <lifted>)` in the theorem statement. Probe result on the
hash4 lifted DAG: **3341 DAG nodes, but dag2term acl2-count = 5.8×10⁷⁹.** Same
term/shared-DAG wall as the 2022-constraint lex ladder. `defthm-axe-r1cs` cannot
state the hash4 layer. Confirmed, dead at this scale.

### Why citability is genuinely hard here.
`verify-r1cs` closes only because its clause processor runs a `:subst` phase
(Gaussian-style elimination of the 355 internal wires). Ordinary `defthm`
rewriting cannot reproduce that substitution. The b1.9a IsZero-block citable
lemma did the substitution by hand because it was 2 constraints / 1 wire; the
hash4 layer is 356 constraints / 355 wires — the explicitly-deferred b1.9b-class
telescoping effort.

### Two credible routes (both large — pick before investing):

1. **Composition (what the spike plan assumed).** Make one hash4 layer citable
   via hand-substitution direct-unfold (b1.9b-class), then transport ×16 with
   rename-cons, glue the select-block (small, b1.9a-style direct-unfold per
   layer), compose into a `root = iterated-hash4(...)` theorem. Modular; reuses
   the single hash4 proof. Cost: the hand-substitution of 355 wires is the hard,
   slow part.

2. **Whole-path `verify-r1cs` (no composition, no citability wall).** Export a
   `QuadPathGadget` wrapping all 16 layers (≈6000 constraints), write a
   `quad-path-r1cs-axe` spec (position decode + selects + 16× hash4 rounds),
   generate ~1136 pow17 chains (16×71, `gen-hash4-proof.py` already does the
   per-S-box emission), and run one `verify-r1cs`. Anonymous — same status class
   as poseidon2/nullifier/hash4, fine for a `proved` gate row. `verify-r1cs`
   scales here (it proved 5568-constraint AssetRegistryGap operand canonicity via
   shared DAG, no dag2term). Cost: authoring the quad-path spec with the select
   logic, and getting the Select constraints to discharge under the prover.

Recommendation: **route 2** (whole-path verify-r1cs) is the lower-risk path to a
`proved` quad-path row — it sidesteps the measured dag2term wall and the
355-wire hand-substitution entirely, and the chain emission is already
automated. Route 1 only wins if a citable, reusable layer lemma is independently
wanted.
