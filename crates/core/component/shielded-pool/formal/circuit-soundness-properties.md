| `NO-DOUBLE-SPEND` | transfer, NoteReshape, shielded ICS-20 withdrawal | Each real input nullifier is uniquely determined by `(NK, commitment, position)` and the commitment path reaches the public anchor. NoteReshape dummy nullifiers are domain-separated. | `Nullifier`; `VerifyStateCommitmentPath`; dummy seed logic in transfer, NoteReshape, and shielded withdrawal. | `check_nullifier_unspent`; `nullify` in action handlers. | Prover tries to spend the same note twice or collide a dummy nullifier with a real one. | `composed` |
| `BALANCE-CONSERVATION` | all circuit families | Input amounts minus output/withdrawal amounts must equal the public balance commitment under the committed asset id. | `computeTransferNetBalanceCommitment`; `AssertEquivalent` against `BalanceCommitment`. | Batch proof verification and action body extraction bind the public commitment. | Prover creates value or changes withdrawal amount without changing the statement hash. | `refined` |
| `NOTE-OWNERSHIP-SPEND-AUTH` | all spend circuits | The randomized verification key is `RK = AK + r*G`, transmission keys derive from IVK, and authorization signatures bind the effect hash. | `RandomizedVerificationKey`; `DiversifiedTransmissionKey`; `AssertEquivalent` on RK and transmission keys. | `verify_auth_sigs` checks spend auth signatures before execution. | Prover spends a note controlled by another key or reuses a signature on another effect. | `composed` |
| `OUTPUT-WELL-FORMEDNESS` | transfer, NoteReshape, shielded ICS-20 withdrawal | Output commitments open to the note fields in the witness, and recipient/sender compliance leaves bind the intended address, asset, and slot fields. | `NoteCommitmentWithCompressedDivGen`; `ComplianceLeafCommitmentFromCompressed`; output note commitment equality. | Output payloads are inserted only after proof and handler checks pass; dummy NoteReshape outputs are excluded from state. | Prover publishes a commitment unrelated to the encrypted note payload. | `refined` |
| `REGULATED-STATUS-SOUNDNESS` | transfer, shielded ICS-20 withdrawal | Regulated case: `asset_id` must be an asset IMT member under `AssetAnchor`. Both Rust and Go enforce this through `select(is_regulated, is_exact_match, is_in_gap)`. | Rust `verify_asset_registry_imt`; Go `VerifyAssetRegistryIMT` using AssetRegistryGap. | `validate_compliance_anchors` only proves the anchor is live, not the asset's branch semantics. | Prover sets `IsRegulated=false` to route a regulated asset through a branch without asset non-membership proof. | `refined` |
| `CIPHERTEXT-CORRECTNESS` | transfer, shielded ICS-20 withdrawal compliance paths | Regulated compliance ciphertext fields must match in-circuit Poseidon encryption and DLEQ checks, tying Track A ciphertext obligations to circuit acceptance. | Rust `verify_poseidon_encryption` and `verify_dleq_r1cs`; Go `VerifyPoseidonEncryptionTransferDetection` and `VerifyDLEQ`. | Transfer/withdrawal action handlers verify the proof and compliance anchors. | Prover submits ciphertext that decrypts differently from the witness or changes DLEQ metadata. | `composed` |
| `STATEMENT-INTEGRITY` | all circuit families | `ClaimedStatementHash` must hash exactly the semantic public fields intended for the circuit family, in the same order in Rust and Go. | Rust `*_statement_fields`; Go circuit statement-field reconstruction and Poseidon hash. | New Rust/Go differential compares reconstructed Go vectors against Rust-emitted vectors. | Prover exploits a Rust/Go field-order mismatch or a length-only ABI check. | `composed` |
| `NOTE-RESHAPE-LEAN-SOUNDNESS` | NoteReshape 2→1, 4→1, 8→1, and 1→8 (`note_reshape2x1`, `note_reshape4x1`, `note_reshape8x1`, `note_reshape1x8`) | Handwritten `Protocol.NoteReshape.Semantics` defines the accepted action relation independently of generated circuit modules. Exact deployed rows generate typed circuit facts; handwritten adapters must derive shape, padding, canonical address, input/output commitment, membership, authorization-key, conservation, and statement-binding obligations before the family-independent refinement theorem yields `Valid`. Caller-supplied semantic projections are forbidden. | The four coverage reports bind 37,559, 64,784, 117,526, and 29,196 exact deployed rows to generated contracts, templates, `Bounds.lean`, `Capstone.lean`, and `CircuitFacts.lean`. Compiler-labelled LCs and permutation-certified seams prove that each shared DTK output is exactly the point consumed by transmission compression. CI pins the independent semantic digest, rejects generated imports in the protocol spec, classifies every witness field, byte-matches fresh SR1CS/manifests, and proves/verifies with the bundled deployed keys. | Action handlers supply signature verification for every RK, nullifier freshness, and state-transition preconditions. Correctness of the gnark compiler/backend and SNARK cryptography remains a named trust assumption. The remaining concrete semantic adapters and final deployed-to-`Valid` theorem are open. | Prover satisfies exact deployed relations while trying to exploit a missing semantic join, split address representation, dummy/real substitution, membership bypass, value creation, RK substitution, or statement mismatch. | `open` |
| `TRANSFER-LEAN-SOUNDNESS` | transfer | The checked-in transfer Define-model composes spend/output note commitments, nullifiers, state/asset paths, ACK derivation, DLEQ response checks, regulated threshold selection, transfer salts, Poseidon compliance ciphertexts, net-balance commitment, and the rolling statement hash into one Lean soundness theorem; a Go Define wiring transcript is byte-checked against the Lean transcript, and the compiled `.sr1cs` has an independently checked partition manifest. | Extracted Poseidon rate-1/rate-5/rate-6/rate-7 gadgets; extracted depth-24 quad path; extracted Decaf377 boundary predicates; RVK/DTK/net-balance bridges; transfer compliance bridges for ACK, shared secrets, salts, DLEQ, threshold/branch selection, dummy mux, and encryption; final statement hash equality; wiring-transcript fidelity for call order and semantic inputs/outputs; compiled-constraint manifest/report binding every `.sr1cs` row to exactly one segment and the bundled verifying key. | Action handlers still perform proof verification, nullifier freshness, compliance-anchor validation, and accepted-language checks outside this Lean theorem. Backend SNARK crypto and gadget-segment identity remain named trust assumptions. | Prover satisfies the model while trying to decouple transfer note semantics, compliance ciphertexts, DLEQ statements, regulated branch selection, balance commitment, or statement hash. | `proved` |
| `ZK-PROP-AMOUNT-RANGE-128` | all circuit families | Every amount is `< 2^128` on both sides of the circuit boundary: the in-circuit `ScalarMulLE` decomposition is exactly 128 bits, and the Rust `Amount` wire form cannot represent `>= 2^128` nor alias a smaller value mod the curve order. | `TestAmountRangeBoundIs128Bits` (`tools/gnark/internal/circuits/amount_range_test.go`): `2^128 - 1` satisfiable, `2^128` unsatisfiable for `BalanceCommitment` and `computeTransferNetBalanceCommitment`. | Rust `amount_is_structurally_below_2_pow_128` and `scalar_embedding_of_max_amount_does_not_wrap` (`crates/core/num/src/amount.rs`) reject out-of-range amounts before proving and pin the no-wrap embedding. | Prover inflates supply via a field-overflowing amount the abstract `Int` models never see, or a ladder-width regression silently widens the bound. | `refined` |
| `ZK-PROP-NOTE-RESHAPE-STATEMENT-SEAM` | NoteReshape | Rust statement serialization and Go circuit witness assignment agree on field order, encoding, and hash for exact and padded shapes. | `TestRustGoStatementFieldDifferential` (`tools/gnark/internal/abi`) covers 2→1, 4→1, 8→1, and 1→8; NoteReshape circuit tests cover valid assignments and statement mutations. | Rust witness generation and Go reconstruction use the same manifest-driven shape and statement-field rules. | Prover exploits a Rust/Go wire-order, endianness, or ABI mismatch so a proof verifies against a differently parsed statement. | `refined` |
