# ZK Circuit Soundness Properties

| ID | Circuit(s) | Precise statement | In-circuit assertions | External checks | Adversary view | Status |
| --- | --- | --- | --- | --- | --- | --- |
| `NO-DOUBLE-SPEND` | transfer, consolidate, split, shielded ICS-20 withdrawal | Each real input nullifier is uniquely determined by `(NK, commitment, position)` and the commitment path reaches the public anchor. Dummy nullifiers are domain-separated. | `Nullifier`; `VerifyStateCommitmentPath`; dummy seed logic in transfer and shielded withdrawal. | `check_nullifier_unspent`; `nullify` in action handlers. | Prover tries to spend the same note twice or collide a dummy nullifier with a real one. | `composed` |
| `BALANCE-CONSERVATION` | all circuit families | Input amounts minus output/withdrawal amounts must equal the public balance commitment under the committed asset id. | `computeTransferNetBalanceCommitment`; `AssertEquivalent` against `BalanceCommitment`. | Batch proof verification and action body extraction bind the public commitment. | Prover creates value or changes withdrawal amount without changing the statement hash. | `refined` |
| `NOTE-OWNERSHIP-SPEND-AUTH` | all spend circuits | The randomized verification key is `RK = AK + r*G`, transmission keys derive from IVK, and authorization signatures bind the effect hash. | `RandomizedVerificationKey`; `DiversifiedTransmissionKey`; `AssertEquivalent` on RK and transmission keys. | `verify_auth_sigs` checks spend auth signatures before execution. | Prover spends a note controlled by another key or reuses a signature on another effect. | `composed` |
| `OUTPUT-WELL-FORMEDNESS` | transfer, consolidate, split, shielded ICS-20 withdrawal | Output commitments open to the note fields in the witness, and recipient/sender compliance leaves bind the intended address, asset, and slot fields. | `NoteCommitmentWithCompressedDivGen`; `ComplianceLeafCommitmentFromCompressed`; output note commitment equality. | Output payloads are inserted only after proof and handler checks pass. | Prover publishes a commitment unrelated to the encrypted note payload. | `refined` |
| `REGULATED-STATUS-SOUNDNESS` | transfer, shielded ICS-20 withdrawal | Regulated case: `asset_id` must be an asset IMT member under `AssetAnchor`. Unregulated case: `asset_id` must prove non-membership by a gap. Both Rust and Go enforce this through `select(is_regulated, is_exact_match, is_in_gap)`. | Rust `verify_asset_registry_imt`; Go `VerifyAssetRegistryIMT` using AssetRegistryGap. | `validate_compliance_anchors` only proves the anchor is live, not the asset's branch semantics. | Prover sets `IsRegulated=false` to route a regulated asset through a branch without asset non-membership proof. | `refined` |
| `CIPHERTEXT-CORRECTNESS` | transfer, shielded ICS-20 withdrawal compliance paths | Regulated compliance ciphertext fields must match in-circuit Poseidon encryption and DLEQ checks, tying Track A ciphertext obligations to circuit acceptance. | Rust `verify_poseidon_encryption` and `verify_dleq_r1cs`; Go `VerifyPoseidonEncryptionTransferDetection` and `VerifyDLEQ`. | Transfer/withdrawal action handlers verify the proof and compliance anchors. | Prover submits ciphertext that decrypts differently from the witness or changes DLEQ metadata. | `composed` |
| `STATEMENT-INTEGRITY` | all circuit families | `ClaimedStatementHash` must hash exactly the semantic public fields intended for the circuit family, in the same order in Rust and Go. | Rust `*_statement_fields`; Go circuit statement-field reconstruction and Poseidon hash. | New Rust/Go differential compares reconstructed Go vectors against Rust-emitted vectors. | Prover exploits a Rust/Go field-order mismatch or a length-only ABI check. | `composed` |
