# Soundness Assumption Ledger

The single registry of every assumption the formal-verification stack rests on,
across all subjects. These are exact-construction assumptions for the current
code, not generic textbook summaries. Each row has an owner, rationale,
supporting evidence with an explicit postcondition, a removal path, and the tool
whose verified property consumes it.

**ID prefix = subject domain** (not the tool that checks it):

- `CC-` — compliance ciphertext / DLEQ / Orbis re-encryption cryptography.
- `ZK-` — zk-circuit and shielded-pool cryptography (gnark R1CS bridges, value
  commitment, indexed Merkle tree).
- `MODEL-` — pure formal-model artifacts: the faithfulness of an abstraction or
  a model-checking scope bound — facts about the *model* rather than the
  deployed system.

**`Checked-by`** names the tool whose verified property rests on the row
(`lean`, `tamarin`, `alloy`, `differential`). Tamarin contributes no rows of its
own: its `ProofSound` restriction *imports* the `CC-` DLEQ/RO rows rather than
introducing new assumptions, so those rows read `lean + tamarin import`.

The DLEQ Fiat-Shamir, challenge-truncation, non-malleability, prime-order-group,
and PRE rows below are retained for standalone research models. Transfer V16
contains no DLEQ/PRE relation or transport field, so none is a premise of its
deployed circuit-refinement claim.
