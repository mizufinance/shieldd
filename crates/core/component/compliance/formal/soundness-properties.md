# Compliance Ciphertext Soundness Properties

Each row is phrased from the adversary's point of view. The `ID` column is the
stable machine-checked key used by `scripts/check-soundness-invariants.sh`.

| ID | Goal | Precise statement | Establishing code | Adversary check | Status |
| --- | --- | --- | --- | --- | --- |
| `SECRECY` | Unflagged tier plaintext secrecy. | For regulated transfers, non-authority observers and the issuer must not learn ACK-tier plaintext unless they hold the relevant ACK secret; flagged tiers use DK-designated material. For unregulated transfers, sink keys preserve the shape of the ciphertext but do not create issuer decryptability. | `encrypt_transfer`; `encrypt_tier_bytes`; `decrypt_tier_bytes`; `derive_unregulated_sink_point` | Observer modifies or reads public `c2` and ciphertext; issuer tries DK material on ACK tier. | `proved-symbolic` |
| `DETECTION-CORRECTNESS` | Regulated detection tier correctness. | If `is_regulated=true`, detection ciphertext decrypts under issuer material and the flag corresponds to the in-circuit threshold predicate. If `is_regulated=false`, encryption and DLEQ enforcement are gated off and no issuer-decryptability claim is made. | `verify_poseidon_encryption`; `VerifyPoseidonEncryptionTransferDetection`; `VerifyThresholdFlagSimple` | Prover sets a false flag or uses an unregulated branch to avoid detection. | `proved-symbolic` |
| `DESIGNATED-DECRYPTABILITY` | Tier recipient is the intended ACK/DK holder. | For regulated transfers, each tier's shared secret is derived from the intended ACK or DK point and the same ephemeral randomizer as the published EPK. Unregulated tiers use fixed sink keys only for format compatibility. | `encrypt_transfer`; `DeriveSharedSecretsSpend`; `verify_dleq_r1cs` | Prover creates a ciphertext decryptable by an unintended key while keeping DLEQ valid. | `proved-symbolic` |
| `DLEQ-BINDING` | One randomizer binds EPK, shared point, and metadata. | A Fiat-Shamir DLEQ proof binds `EPK = r*G` and `S = r*ACK` to metadata `(policy, resource, permission, tier, target_timestamp, salt)`, preventing proof reuse across tiers or transfers. | `compute_dleq_native`; `verify_dleq_native`; `verify_dleq_r1cs`; `compute_transfer_dleqs` | Prover lifts a proof from one tier, key, salt, or timestamp into another. | `proved-symbolic` |
| `REPLAY-RESISTANCE` | Metadata uniqueness against replay. | DLEQ metadata includes the tier salt and `target_timestamp`; action handlers reject stale timestamps and stale anchors before execution. | `compute_transfer_dleqs`; `check_timestamp_freshness`; `validate_compliance_anchors` | Network adversary replays a tier or whole transfer under a later block context. | `proved-symbolic` |
| `NO-KEY-CONFUSION` | ACK, DK, and tier domains do not collide. | ACK and DK shared secrets are used under explicit branch logic, DLEQ metadata includes `tier`, and transfer tier ordering is committed into the statement hash. | `encrypt_transfer`; `compute_metadata_hash`; `buildTransferStatementFields` | Issuer or prover swaps ACK/DK material or tier labels while preserving public bytes. | `proved-symbolic` |
| `ANCHOR-FRESHNESS` | Registry keys come from live anchors. | Asset and compliance keys are accepted only when their IMT anchors exist in consensus state and are within the configured validation window. | `validate_compliance_anchors`; `verify_asset_registry_imt`; `VerifyQuadPath` | Prover uses old or fabricated IMT roots for keys. | `proved-symbolic` |
| `IMT-NULLIFIER-STATE` | Nullifier-set and IMT state invariants hold across blocks. | Under the check-then-nullify rule a nullifier is nullified in at most one block (no double spend), and a valid IMT non-membership (gap) witness for a value implies that value is genuinely absent from the leaf set while inserts preserve the sorted linked list. | `check_nullifier_unspent`; `nullify`; `indexed_tree.rs::insert`; `indexed_tree.rs::non_membership_proof` | Prover replays a nullifier in a second block, or forges a gap witness for a value already present in the IMT. | `proved-symbolic` |
| `TX-VALUE-CONSERVATION` | A verifying binding signature forces per-asset value conservation. | With independent per-asset value generators, the summed balance commitment lying in the blinding-only subspace (a verifying binding signature) implies every asset's net signed value is zero, so no transaction inflates supply. | `balance/commitment.rs::Value::commit`; `transaction.rs::binding_verification_key`; `stateless.rs::valid_binding_signature` | Prover assembles an unbalanced action set (net nonzero value on some asset) that still produces a verifying binding signature. | `proved-symbolic` |
| `COMPLIANCE-TIER-FSM` | The compliance audit/tier state machine admits only legal transitions. | Audit status advances only along legal `try_advance` edges, `Complete` is terminal and reachable from every non-terminal state, no transition shortcuts past `Pending`, and exactly four canonical transfer tiers exist in fixed order. | `audit_status.rs::try_advance`; `audit_validation.rs`; `decode_object.rs` (`TransferTierKind`) | Prover drives the audit FSM through an illegal edge, escapes a terminal state, or smuggles a fifth/out-of-order tier. | `proved-symbolic` |
| `ORBIS-DESIGNATED-DECRYPT` | Only the designated issuer recovers an Orbis-sealed seed. | Each re-encryption commitment (`xnc_cmt`) binds to exactly one issuer key; the bound issuer recovers exactly the sealed seed and no other issuer recovers anything, mirroring the on-chain authorization relation. | `orbis_interop.rs::compute_reencrypt_commitment`; `verify_reencrypt_proof`; `recover_seed` | Prover or a non-designated issuer recovers the seed from a commitment bound to a different issuer key. | `proved-symbolic` |
| `ZK-PROP-C2X1-STATEMENT-SUFFICIENT` | The consolidate2x1 7-field public statement is sufficient for ledger safety. | Given the circuit's witness bindings (each `null_i` binds a spent input via `nf`, each `rk_i` binds its spend-auth key, `outCm` binds the output note) and the chain acceptance rule (anchor is historical; the fail-closed nullifier set rejects any repeated nullifier across or within actions), an adversary who can prove any satisfiable statement still cannot double-spend a note, inflate value, or bypass spend authorization. Input distinctness is NOT a circuit constraint — it is emergent from the fail-closed sequential nullifier insert; value conservation is delegated to the binding signature (`TX-VALUE-CONSERVATION`), since the net-balance field is a blinded commitment, not an in-circuit note-value equation. | `note_reshape_circuit.go` (nullifier, rvk, note-commitment, net-balance segs); `note_reshape.rs::execute` (check-then-nullify loops); `sct/nullifier_tree.rs::insert_batch` (fail-closed dup rejection); `sct/tree.rs::check_claimed_anchor`; `stateless.rs::valid_binding_signature` | Prover mints an accepted action that reuses a note in both input slots or across two actions, creates value while keeping the statement satisfiable, or reuses a spending key the `rk` fields do not pin. | `proved-symbolic` |
| `ZK-PROP-TRANSFER-STATEMENT-SUFFICIENT` | The transfer 83-field public statement is sufficient for ledger safety, including the regulated/compliance surface. | The value surface (anchor, 2 output commitments, balance, 2 nullifiers+rk) mirrors `ZK-PROP-C2X1-STATEMENT-SUFFICIENT` on the same proven substrate; transfer additionally adds two-input dummy handling and a regulated surface. An adversary who can prove any satisfiable statement cannot: double-spend (real or via a dummy slot), inflate value, bypass spend auth, OR spend a **regulated** asset while skipping the compliance-tree binding — because `AssetRegistryGap` pins `is_regulated` to registry membership (`==1` forces exact-match membership when regulated, a valid non-membership gap proof when not), and a dummy input publishes a domain-separated synthetic nullifier that is never a real note's nullifier. The 7 unproven compliance-gadget classes are a regulator-utility tier and are NOT load-bearing for these safety assertions. **Caveat:** F1 (circuit-soundness facts) is a hand-maintained interface to the Lean deployed-bridge layer, not a mechanical binding to the extracted R1CS. | `transfer_circuit.go` (spend/output/rvk/nb segs :424-551; dummy mux :443-455; is_regulated gating :264-318); `indexed_tree.go::VerifyAssetRegistryIMT` :273; `canonical_fq_bits.go::AssetRegistryGap` :171; transfer action handler + `sct/nullifier_tree.rs::insert_batch` (fail-closed) | Prover mints an accepted action that reuses a note, creates value, reuses a spend-auth key the `rk` fields do not pin, spends a registered asset with `is_regulated=0` to skip compliance, or spends a real note through a dummy slot. | `proved-symbolic` |
| `DLEQ-COMPLETENESS` | An honest DLEQ proof always verifies. | For a statement `(g, ack, epk, sp)` with witness `r` (`epk=r·g ∧ sp=r·ack`), the prover's transcript `(R=k·g, R'=k·ack, c, s=k+c·r)` satisfies the verifier equations. | `compute_dleq_native`; `verify_dleq_native`; Lean `lean-dleq/Dleq/Sigma.lean::sigma_complete` (artifact `lean-dleq-artifact.txt`; `CC-ASSUME-DECAF377-PRIME-ORDER-GROUP`) | — (correctness obligation; an honest proof that failed would break liveness). | `proved-computational` |
| `DLEQ-SPECIAL-SOUNDNESS` | Two accepting transcripts yield the witness. | From two accepting transcripts sharing `(R,R')` with distinct challenges `c≠c'`, the extractor `r=(s−s')·(c−c')⁻¹` satisfies `epk=r·g ∧ sp=r·ack`; `(c−c')` is invertible mod `q` by truncation. | `verify_dleq_native`; Lean `lean-dleq/Dleq/Sigma.lean::sigma_speciallySound` (artifact `lean-dleq-artifact.txt`; `CC-ASSUME-DECAF377-PRIME-ORDER-GROUP`) | Prover produces two accepting transcripts on the same commitment without knowing `r`. | `proved-computational` |
| `DLEQ-HVZK` | DLEQ proofs leak nothing about `r`. | The simulator that samples `(c,s)` and sets `R=s·g−c·epk`, `R'=s·ack−c·sp` produces transcripts identically distributed to honest ones, so accepted proofs are zero-knowledge for the shared scalar. | `compute_dleq_native`; Lean `lean-dleq/Dleq/Sigma.lean::sigma_hvzk` (artifact `lean-dleq-artifact.txt`; `CC-ASSUME-DECAF377-PRIME-ORDER-GROUP`) | Verifier or observer extracts information about `r` from a proof. | `proved-computational` |
| `DLEQ-CHALLENGE-TRUNCATION` | 250-bit challenge truncation preserves soundness. | `fq_to_challenge_scalar` keeps the low `Fr::MODULUS_BIT_SIZE−1 = 250` bits; since `2^250 < q` the challenge set injects into `Z_q` and nonzero challenge differences are units mod the prime `q`, so the special-soundness extractor is well-defined. The 250→`Fr` reduction is non-uniform by a factor ≤ 1.07 (≤0.1-bit soundness loss, `CC-ASSUME-CHALLENGE-TRUNCATION-NEGL`); kept byte-identical to upstream Orbis `fq_to_challenge_scalar` for challenge parity. | `fq_to_challenge_scalar`; Lean `lean-dleq/Dleq/Challenge.lean::emb_injective` (artifact `lean-dleq-artifact.txt`; `CC-ASSUME-DECAF377-PRIME-ORDER-GROUP`, `CC-ASSUME-CHALLENGE-TRUNCATION-NEGL`) | Prover exploits truncation bias/collisions to forge or malleate a challenge. | `proved-computational` |
| `DLEQ-FS-KNOWLEDGE-SOUNDNESS` | Fiat-Shamir DLEQ is knowledge-sound in the ROM. | Any prover making at most `q_h` random-oracle queries that outputs an accepting non-interactive proof yields a witness via the extractor, except with probability `≤ 1.07·(q_h+1)/2^250 + ε_ss` (the `1.07` is the truncation non-uniformity, `CC-ASSUME-CHALLENGE-TRUNCATION-NEGL`). **Scope:** the Lean `dleq_fs_knowledge_soundness` proves EUF-NMA for a single honestly-generated statement (weak-FS RO query `(m, R, R')`); statement-binding across adversarially-chosen statements — what `crypto.rs` achieves by also hashing `(g,ack,epk,sp)` — is tracked by `CC-FIND-DLEQ-WEAK-FS` until the strong-FS model (Step B) lands. | `compute_dleq_native`; `verify_dleq_native`; `compute_transfer_dleqs`; Lean `lean-dleq/Dleq/FiatShamir.lean::dleq_fs_knowledge_soundness` (artifact `lean-dleq-artifact.txt`; `CC-ASSUME-DECAF377-PRIME-ORDER-GROUP`, `CC-ASSUME-POSEIDON-RO`) | Prover forges an accepting proof without a witness, or lifts a proof across tiers/transfers. | `proved-computational` |
