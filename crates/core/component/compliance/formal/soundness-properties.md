# Compliance Ciphertext Soundness Properties

Each row is phrased from the adversary's point of view. The `ID` column is the
stable machine-checked key used by `scripts/check-soundness-invariants.sh`.

| ID | Goal | Precise statement | Establishing code | Adversary check | Status |
| --- | --- | --- | --- | --- | --- |
| `SECRECY` | Unflagged tier plaintext secrecy. | For regulated transfers, non-authority observers and the issuer must not learn ACK-tier plaintext unless they hold the relevant ACK secret; flagged tiers use DK-designated material. For unregulated transfers, sink keys preserve the shape of the ciphertext but do not create issuer decryptability. | `encrypt_transfer`; `encrypt_tier_bytes`; `decrypt_tier_bytes`; `derive_unregulated_sink_point` | Observer modifies or reads public `c2` and ciphertext; issuer tries DK material on ACK tier. | `proved-symbolic` |
| `DETECTION-CORRECTNESS` | Regulated detection tier correctness. | If `is_regulated=true`, detection ciphertext decrypts under issuer material and the flag corresponds to the in-circuit threshold predicate. If `is_regulated=false`, encryption and DLEQ enforcement are gated off and no issuer-decryptability claim is made. | `verify_poseidon_encryption`; `VerifyPoseidonEncryptionTransferDetection`; `VerifyThresholdFlagSimple` | Prover sets a false flag or uses an unregulated branch to avoid detection. | `proved-symbolic` |
| `DESIGNATED-DECRYPTABILITY` | Tier recipient is the intended ACK/DK holder. | For regulated transfers, each tier's shared secret is derived from the intended ACK or DK point and the same ephemeral randomizer as the published EPK. Unregulated tiers use fixed sink keys only for format compatibility. | `encrypt_transfer`; `DeriveSharedSecretsSpend`; `verify_dleq_r1cs` | Prover creates a ciphertext decryptable by an unintended key while keeping DLEQ valid. | `proved-symbolic` |
| `DLEQ-BINDING` | One randomizer binds EPK, shared point, and metadata. | A Fiat-Shamir DLEQ proof binds `EPK = r*G` and `S = r*ACK` to metadata `(policy, resource, permission, tier, target_timestamp, salt)`, preventing proof reuse across tiers or transfers. | `compute_dleq_native`; `verify_dleq_native`; `verify_dleq_r1cs`; `compute_transfer_dleqs` | Prover lifts a proof from one tier, key, salt, or timestamp into another. | `proved-symbolic` |
| `REPLAY-RESISTANCE` | Metadata uniqueness against replay. | DLEQ metadata includes the tier salt and `target_timestamp`; action handlers reject stale timestamps and stale anchors before execution. | `compute_transfer_dleqs`; `check_timestamp_freshness`; `validate_compliance_anchors` | Network adversary replays a tier or whole transfer under a later block context. | `proved-symbolic` |
| `NO-KEY-CONFUSION` | ACK, DK, and tier domains do not collide. | ACK and DK shared secrets are used under explicit branch logic, DLEQ metadata includes `tier`, and transfer tier ordering is committed into the statement hash. | `encrypt_transfer`; `compute_metadata_hash`; `buildTransferStatementFields` | Issuer or prover swaps ACK/DK material or tier labels while preserving public bytes. | `proved-symbolic` |
| `ANCHOR-FRESHNESS` | Registry keys come from live anchors. | Asset and compliance keys are accepted only when their IMT anchors exist in consensus state and are within the configured validation window. | `validate_compliance_anchors`; `verify_asset_registry_imt`; `VerifyQuadPath` | Prover uses old or fabricated IMT roots for keys. | `proved-symbolic` |
