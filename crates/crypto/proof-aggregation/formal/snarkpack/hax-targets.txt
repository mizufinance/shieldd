# Partial extraction targets for SnarkPack formal verification.
#
# hax extraction should keep the executed Rust functions as the source of truth.
# Any duplicate formal-only traversal branch must be recorded in
# hax-extraction-boundary.md and parity-tested under cfg(hax).
# The S2-23 coefficient-vector graph is vendored in
# formal/lean-ipp/Ipp/Extracted/PolynomialCoefficientsGenerated.lean; its
# refinement theorem remains a separate proof-session deliverable.
# The S2-26 public-input fold graph is vendored in
# formal/lean-ipp/Ipp/Extracted/Groth16VerifierGenerated.lean; its refinement
# theorem remains the S2-27 proof-session deliverable.
# The S2-28 prepared-PPE graph is vendored in the same generated module; its
# refinement theorem remains the S2-29 proof-session deliverable. The scoped
# Charon target is verify_ppe_core; the concrete Pairing wrapper is not part of
# the extracted graph.
# The S2-25 base-commitment graph is vendored in
# formal/lean-ipp/Ipp/Extracted/BaseCommitmentGenerated.lean. Its explicit
# result/effect/input records preserve all four effect failures; the concrete
# DoublyHomomorphicCommitment/InnerProduct adapter is not extracted.
# The S2-30 verifier graph is vendored in
# formal/lean-ipp/Ipp/Extracted/VerifyTippMippGenerated.lean. Its typed
# challenge effect, five-lane fold state, and terminal checks are extracted;
# the concrete Arkworks adapter remains outside the graph.
# The S2-34 combined-check graph is vendored in
# formal/lean-ipp/Ipp/Extracted/CombinedChecksGenerated.lean. Its explicit
# combined records, count checks, PPE delegation, result propagation, and
# trace-preserving TIPP effect are extracted; S2-35 proves its refinement.
# The S2-36 aggregate core graph is vendored in
# formal/lean-ipp/Ipp/Extracted/AggregateVerifierGenerated.lean. Its typed
# effect carries chronological randomizer attempts and the combined result;
# the handwritten capstone composes it with S2-35 under the named byte/digest
# trace correspondence.
