# Poseidon parameter provenance (H4)

**Status: DRAFT — pending frontier/human review.** This memo is the document

round-count/MDS provenance and cite the security-margin analysis for this

## What is deployed

One parameter set per rate 1–7 (state widths t = 2–8) over the BLS12-377
scalar field Fq, all with:

- S-box α = 17 (smallest-depth positive exponent with gcd(α, q−1) = 1 for
  this field; α = 5 fails the gcd condition on BLS12-377 Fq),
- R_F = 8 full rounds, R_P = 31 partial rounds,
- per-rate MDS matrix (t² entries) and round constants (t × 39 entries).

Canonical copy: `tools/gnark/internal/primitives/vectors/phase05_vectors.json`
(embedded via `vectors.go`); the same set is what the Rust side uses through
the `poseidon377` crate.

## Where the numbers come from

- The parameters are Penumbra's `poseidon377` instantiation for BLS12-377,
  consumed as crate v1.2.0 via the `mizufinance/poseidon377` fork
  (Cargo.lock pin `72e3d94d…`, branch `main`). The fork exists for packaging;
  its parameter values match the vendored JSON (see mechanical pins below).
- They were generated by Penumbra's `poseidon-paramgen`, a from-the-paper Rust
  reimplementation of the Poseidon parameter-generation procedure at security
  level M = 128, including automated optimal-α selection. The methodology —
  and every deviation from the paper's sample scripts — is documented in-repo
  at `docs/protocol/src/crypto/poseidon/paramgen.md` (S-box selection via
  shortest addition chains, round-number formulas with the paper's security
  margins, MDS construction with the paper's algebraic checks).
- The round counts satisfy the Poseidon paper's bounds against statistical,
  interpolation, and Gröbner-basis attacks for α = 17, t ≤ 8, M = 128, with
  the paper's recommended +2 full / +7.5 % partial security margin applied by
  `poseidon-paramgen`. Penumbra's `poseidon-paramgen`/`poseidon377` underwent
  an external cryptography review (NCC Group, 2022) covering exactly this
  generation procedure.

## Mechanical pins (already in CI)

- `poseidon377.go:154` (and `:199` on the native path) hard-rejects any config
  whose α ≠ 17; `:160`–`:166` check MDS size = t² and round-constant vector
  length = t × (R_F + R_P).
- `scripts/check_poseidon377_parity.sh` regenerates `Vectors.lean` via
  `gnarkctl export-poseidon-lean` and `#guard`-checks Lean-side outputs
  against Go-native ones — so the JSON, the Go gadget, and the Lean spec
  cannot silently diverge on parameters.
- Domain separators (spend/note-commit/nullifier/…) live in the same JSON and
  flow through the same parity gate.
